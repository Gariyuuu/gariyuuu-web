# CLAUDE.md — gariyuuu-web operating manual

Personal site for Gary Wang, live in production at **https://gariyuuu.com**. This is
NOT a sandbox — changes here are visible to the public and to anyone he sends the
dashboard link to. Treat every change as a real deploy.

Read `HANDOFF.md` first if you're starting a session cold. This file covers
conventions and rules; `PROJECT_STATE.md` covers exactly where things stand right now.

Current task: **T-001** (blocked: needs user confirmation) — see `TASKS.md`.

## What this project is

A Next.js 16 (App Router) site with four surfaces:
1. Landing page (`/`) — pitches the self-hosted AI platform and links out.
2. About/résumé (`/about`) — Gary's real bio, experience, education.
3. Public chat demo (`/chat`) — a rate-limited, streaming chat against Gary's
   self-hosted model ("Yuu v1.1" = Qwen3-8B; the API's `model` field still
   sends the literal string `"Yuu no Sekai"` — see FEATURES.md), proxied
   server-side.
4. Password-gated usage dashboard (`/dashboard`) — shows live per-app token/request
   usage pulled from the AI platform's admin API. Gated by email allowlist + a
   single shared password (see SECURITY.md for exactly how, and its limits).

There is no database in this repo. The only external system this app talks to is
the AI platform (`api.gariyuuu.com`, a separate repo: `~/Projects/ai-platform`),
via two proxied API routes.

## Critical rules

- **This is production.** Don't `git push` unless explicitly asked — the user
  treats pushing/deploying as their own call (Vercel auto-deploys on push to
  `main`, see DEPLOYMENT.md).
- **Never write real secret values into any file that gets committed.** No API
  keys, no `DASHBOARD_PASSWORD`, no `AI_PLATFORM_ADMIN_SECRET`. `.env.local` is
  gitignored and must stay that way — only `.env.example` (placeholders, empty
  values) is tracked.
- **All three of `DASHBOARD_SESSION_SECRET`, `DASHBOARD_PASSWORD`, and
  `DASHBOARD_ALLOWED_EMAILS`** must be set together or the dashboard auth route
  fails closed (returns 500 "Dashboard is not configured"). Same for the AI
  platform envs and `/api/chat` and `/api/dashboard/usage`.
- **Don't touch the `<!-- BEGIN:nextjs-agent-rules -->` block in `AGENTS.md`.**
  It's regenerated by `next dev` itself (see the comment inside it) — editing it
  by hand just gets overwritten, and removing it from a diff without committing
  the removal recreates the uncommitted change on every dev-server start.
- **Respect `prefers-reduced-motion`.** Both `MatrixRain` and `BootIntro` check
  this media query and disable/skip animation — keep that behavior if you touch
  either component.
- **The boot intro plays on every page load, on every route** (mounted in
  `src/app/layout.tsx`, not per-page). If it feels heavy-handed, that's a design
  choice already made — don't silently remove it; ask first.
- **The theme is a single fixed dark "hacker" palette** (black background, green
  `--accent` / cyan `--accent-2`, `Share_Tech_Mono` font) defined in
  `src/app/globals.css`. An earlier version of this site had a 6-palette
  light/dark theme picker (see git history, commit `40635cf`); it was
  deliberately replaced by the current single dark theme in commit `0d61741`.
  There is no theme picker in the current code — if you see stale notes
  referencing one, they're describing a superseded state.
- **`PROJECTS` in `src/lib/projects.ts` is the single source of truth** for the
  `/projects` and `/` project listings. Live URLs there are asserted to have
  been verified (curl'd 200 or cross-checked), not guessed — keep that standard
  if you add entries.

## Conventions

- TypeScript, App Router, server components by default; `"use client"` only on
  components that need state/effects/browser APIs (`boot-intro.tsx`,
  `matrix-rain.tsx`, `chat-widget.tsx`, `dashboard-login-form.tsx`,
  `usage-dashboard.tsx`).
- Styling is Tailwind v4 (`@import "tailwindcss"` + `@theme inline` in
  `globals.css`), plus a handful of hand-written utility classes (`.card`,
  `.gradient-text`, `.neon`) and keyframe animations in the same file. No
  component library.
- API routes under `src/app/api/**` are thin proxies with `runtime = "nodejs"`
  (needed for `crypto` in the dashboard auth route) — they validate input, call
  an upstream, and pass through/shape the response. Keep that pattern.
- No database, no ORM, no auth provider (no Clerk/NextAuth/etc.) — the dashboard
  gate is hand-rolled (`src/lib/dashboard-auth.ts`). Don't add a dependency for
  this without discussing it; it's intentionally minimal for a low-stakes gate.
